Version 0.5.1 verification

PassedCompatibility observationsWindows acceptance still required

The 0.5.1 update passed 110 required Forge GameTests with the full pinned pack on October 19, 2026. Crew reward checks cover full per-contributor credits, XP and ordinary items; exclusion of uninvolved members; offline saved receipts; persistence and duplicate-claim protection; crew changes and captain imports; old-save completion guards; single shared ships and fruit boxes; fallback prize recipients; repeatable runs; full-inventory deferral; actual partial delivery hand-ins; exact refunds retaining item names and data; atomic failed deliveries; native Log Pose contribution tracking; and the loaded recipe fixes.

The 0.5.1 conversation reader uses a separate document area, full wrapped titles, complete text lines and separate scrolling/navigation controls. Compact windows use Browse and Choices drawers; larger windows keep the quest sidebar and a paginated action dock. NPC dialogue retains faction reactions and quest updates, and links directly to that resident's quest rows. All 77 screen/action layout combinations passed, including compact windows, breakpoint boundaries, empty and short documents, 1–12 wrapped title lines and full-document scrolling. The separate audio lifecycle regression also passed.

A required built-in compatibility datapack removes the golden staff recipe that conflicted with chest keys. Three vertical gold ingots now uniquely craft the key. Three vertical iron ingots craft the Mine Mine no Mi pipe; adding a stick beside the bottom ingot crafts the Mine Piece pipe. Tests use the actual loaded recipe manager and verify shifted/mirrored grids, pack priority and preserved staff/spear conversions. Existing staff items remain available.

All 37 third-party downloads retain their locked hashes and sizes. The dependency audit resolves 44 mod IDs and 103 dependency declarations. This patch keeps the 0.5.0 story expansion. City population now surveys persistent 64-block quarters throughout mapped islands and has no lifetime neighborhood cap. Native map fixture checks cover ten actual streets across Goa and five other cities; isolated GameTests cover the survey, eight service roles, saved slot identities, indoor budget separation and wide city materials. These are coverage checks, not a full played-world population soak. Small Ships speed and acceleration are multiplied by 1.6 after native upgrades; seven native hulls and non-compounding settings are covered by a GameTest. Item entities reject fire/lava damage while retaining their stacks. Town block protection tests include TNT, native fruit terrain mutation, ordinary building and mapped island bounds. The journal protocol is updated; host and friends must use the same 0.5.1 pack.

An earlier 0.5.1 production-format client initialized the title screen on macOS. The final build loaded the pinned mods and resources, then exited cleanly before a visible title screen; full client startup remains to be confirmed. Expected offline-profile authorization errors and existing upstream asset warnings appeared. This does not replace a visual dialogue or co-op playthrough.

The recipe audit compared 105,129 possible ordinary crafting pairs across 1,703 loaded recipes, found zero crafting/processing/smithing conflicts, and validated 41 native smithing recipes plus 17 sampled special crafting recipes. Intentional stonecutting choices are recorded separately.

The native Minecraft window is not exposed to the available UI automation surface. Automated layout checks are not a visual dialogue playthrough. Windows rendering, faster sailing feel and two-computer remote co-op still require acceptance testing. Back up the whole world before upgrading. Existing completed quests are not paid retroactively. Supplies deposited while solo remain assigned to the solo quest if you form a new crew; complete those deliveries before switching your quest group.

Validation — Grand Line Odyssey 0.2.0

Build date: 2026-10-14. Target: Windows, Minecraft Java 1.20.1, Forge 47.4.0, 64-bit Java 17. Validation ran on an Apple Silicon Mac. This record separates measured checks from the Windows gameplay acceptance still outstanding.

Passed

  • Fruit bridge: all 40 named Mine Piece items pass the real compatibility filters, can be eaten, store native powers and cycle through available moves. A paid Mochi technique starts its native combat skill and consumes energy; Azure Dragon changes its native form attribute. Tests cover cross-system second-fruit protection, exact broker payments, alternate-fruit exchanges, training, and fruit/capacity persistence through player save/load. These are server checks, not a visual playtest of all moves or transformations.
  • The 0.2.0 production client completed startup on macOS with the fruit bridge and registered key bindings. The later one-for-one exchange change passed the final server suite; the client UI did not change after that startup check.
  • Original addon compiled and reobfuscated with ForgeGradle 6.0.54 and Gradle 8.8. The release JAR excludes GameTest classes and embeds the original menu image.
  • 39 required Forge GameTests passed with all locked server-compatible mods loaded. This is a real Forge game server, not a mocked Minecraft runtime.
  • Contract tests check exact cargo consumption, prerequisite gating, no duplicate rewards, inventory charging, travel filtering, supply cooldown and persistence.
  • Integration tests load the real world catalogue, Log Pose data, world preset, registered rewards and native ship items. The Galleon test delivers the actual ship item once and instantiates its entity type.
  • Campaign tests validate all 76 chapters against registered islands, boss entity types and rewards; one-time allegiance, contact proximity and ownership, chapter claims, gifts, wardrobe purchases and faction synchronization.
  • Memory/rival tests check bounded memories, persistent data copied across player replacement, earned discounts and paid truces. They do not simulate an entire campaign or a multi-hour sequence of rival fights.
  • AI tests use a real local mock HTTP server to verify the Ollama request body, bounded context, output cleaning and error behavior. No actual language model was downloaded or benchmarked; model dialogue is optional and disabled.
  • All 33 downloaded artifacts match locked sizes and SHA-1/SHA-512 hashes. The dependency audit covers 40 mod IDs including embedded libraries, and 95 dependency declarations. The custom addon is a separate release JAR.
  • The production-format client loaded the actual locked JARs, native ship libraries, shader framework and UI additions. Its log confirms the custom title screen initialized at 427 × 240 GUI coordinates and startup completed.
  • An original resource patch replaces four legacy GLSL 1.10 post-processing stages with GLSL 1.50 implementations. The previous Haki aura shader-load exception is absent in the final startup check. Missing Mine Piece weapon parent references and the alternate Goro fruit texture reference are also repaired without copying third-party textures or models.
  • The 0.2.0 website was exercised in the browser: the update JAR triggered a download, install/update tabs switched instructions, and the copy button reported success. Searching Mochi with the Mine Piece category returned one entry; an unknown search showed the empty state, and Clear filters restored all 379 entries. The ship guide rendered its navigation and tables correctly. At a 390-pixel viewport the home page had no horizontal overflow. No browser console errors were reported during these checks.
  • The website audit checks local links, anchors and CSS assets in the source preview, release folder, Windows ZIP and installed-instance guides. All pass. The website works from extracted files without a web server; downloads remain relative to the release files. The localhost preview is not a public website.
  • The .mrpack and Windows handoff are checked for ZIP integrity, exact lock correspondence, addon inclusion, disabled default shaders and client-only e4mc placement. SHA-256 sums are supplied with the release artifacts.

Compatibility observations

Forge is pinned to 47.4.0 because Pehkui's menu mixin failed against 47.4.10 in this development environment. Do not independently update the loader or selected mods while comparing test results.

The development client profile cannot remap the released e4mc mixins correctly; production-format startup is the meaningful client check used here. The world mod also reports some nonfatal development mapping warnings during GameTests.

Production startup still logs a Valkyrien Skies sculk mixin warning, Oculus's expected Embeddium modification notice, missing textures on upstream test/debug blocks, and unused shader samplers. These did not prevent startup; they are not proof that every affected feature works. The isolated offline test profile also cannot obtain multiplayer profile keys or authorize Realms. No public e4mc session was opened, and no user Minecraft credentials were used.

The native game window was unavailable to the UI automation surface. The custom menu was compiled and its initialization observed in the real client logs; button navigation and visual layout were not manually certified. Resource patches load, but effects during combat and every outfit/model still need visual inspection. There are no FPS measurements or long-term world soak results.

Windows acceptance still required

  1. Import the .mrpack with Java 17; confirm the One Piece menu, Captain's Guide, singleplayer, multiplayer, Mods and Options navigation at your GUI scale.
  2. Create a Survival One Mine Piece world. Check starter items, native character creation, /story align, one-time /story embark and /voyage.
  3. Earn and place a Cog and Galleon; sail, fire cannonballs, carry a friend, dock, save and reload. Build and assemble a small Eureka test hull too.
  4. Discover islands, complete Log Pose activities and report a chapter beside your contact. Verify shared boss credit, progression and death/respawn.
  5. Eat a fruit; test selected powers, Haki effects, water penalties and equipment. Check inventory sorting and rebind conflicts before serious combat.
  6. Enable Complementary on Low; inspect water, moving ships, NPC models and abilities. Raise quality only after measuring your PC's performance.
  7. Open to LAN and join from a second licensed Java account on another internet connection. Verify inventories, fights and ship synchronization. Close and reopen the world, use the current relay address and confirm saved progress.
  8. If wanted, install Ollama and enable the local model on the host. Check memory use, response speed and lore quality while the game is running.

This is an initial playable build candidate. It is not a certified recreation of every manga scene, nor a guarantee of every mod interaction or endless AI novelty. The supplied guides identify the adaptations and missing exact bosses.
