Method and limits

  • The input is the live server registry with resolved ingredient tags.
  • Ordinary crafting comparisons allow horizontal mirrors, overlapping tags, repeated ingredients, and shaped versus shapeless matches.
  • Each crafting conflict includes a concrete 3×3 grid for confirmation against both native Recipe.matches methods.
  • Cooking collisions are compared only within the same recipe type; multiple stonecutter choices are intentional.
  • Smithing native probes execute matches and assemble with representative inputs and required quantities; overlap candidates still need both native matchers on the supplied witness.
  • Special crafting probes use one representative valid grid/NBT state per recipe, checking native matching, assembly, remaining items, expected state and recipe-manager selection.
  • Each special sample is also tested against every loaded crafting recipe to detect different outputs for that exact grid.
  • Representative native samples do not exhaust all NBT, color, enchantment or ingredient combinations; unprobed custom predicates remain explicitly deferred.
  • This checks loaded recipes, not whether every registered item is craftable; boss drops, trade goods and creative-only items may intentionally have no recipe.
